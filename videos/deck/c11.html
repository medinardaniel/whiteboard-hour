11Cache with a short TTL

A small, very fast memory (Redis) holding recent answers. The TTL is how long a copy lives before it's fetched again.

Think of it as

A sticky note with today's specials, rewritten every 2 seconds.

Use it for

Slots leftMenuCatalog
Scenario. Game day: 20,000 people refresh 'slots left', about 500 requests a second.
Without it
  1. 500 identical database queries every second
With it
  1. First request every 2 s reads the database and saves to Redis
  2. Everyone else gets the Redis copy in under 1 ms
  3. Database load: 1 query per 2 s
  4. Stale '3 left'? Checkout's conditional update says sold out
Why it works2-second-old numbers are fine for browsing; the sale is still decided by the database.
"Cached for 2 s. It's a hint; the database is the truth."

Related terms

TTLTime to live: how long a cached copy is kept.
InvalidationDeleting copies on every change. Harder than a short TTL.
StampedeA hot copy expires and thousands hit the database. Let one refresh.
Hot keyOne item everyone reads. Also keep a 1 s copy in each server.
