10Idempotency key

A random id for each user action. The server saves it with a uniqueness rule; if it arrives again, it returns the first result instead of repeating.

Think of it as

A numbered ticket: show it twice, get served once.

Use it for

No double chargeEvery create or chargeEvery webhook
Scenario. A customer on a train taps 'Place order'. The order is created, but the reply is lost in a tunnel.
Without it
  1. The app retries
  2. The server creates a second order and charges again
With it
  1. The app retries with the same key, a7f3
  2. Server finds a7f3 and returns the original order
  3. Order id also sent to Stripe as its key: one charge
Why it worksRetries are unavoidable on real networks. Without the key, each one is a possible double charge.
"A client key with a unique constraint, the same key passed to Stripe, and webhook event ids deduped."

Related terms

IdempotentDoing it twice has the same effect as doing it once.
Unique constraintThe rule that rejects duplicates. Also stops double booking.
Webhook dedupeSave Stripe's event id and ignore repeats.
Exactly onceNot achievable. You get 'at least once, repeats harmless'.
