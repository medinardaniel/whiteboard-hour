All components (optional reference)

Skip this for now. The Components page has the 23 you need. Come back here only to look something up.

TLDR. Most small-business designs need only about eight parts: CDN, load balancer, a stateless API, one managed Postgres, a cache, a queue with workers, a scheduled job, and a third-party payment provider. Everything else is an answer to a specific number or failure. For each part, know what it is, when to use it, what it costs you, and the one sentence to say in the interview.

Product names are listed as AWS / Azure / GCP / others.

1. Edge: everything before your servers

DNS
What it is
Turns pizza.com into an IP address
When to use it
Always
Trade-off / interview line
Low TTL before a launch, so you can redirect traffic fast
Products
Route 53 / Azure DNS / Cloud DNS / Cloudflare
CDN (content delivery network)
What it is
Servers around the world that cache your static files (HTML, JS, images) and serve them close to users
When to use it
Always for static content; also short-TTL caching of public JSON (menu, catalog)
Trade-off / interview line
Cheapest spike defense. Takes most traffic off your API. "Cached content can be stale for up to the TTL."
Products
CloudFront / Azure Front Door / Cloud CDN / Cloudflare, Fastly
WAF (web application firewall)
What it is
Filters bad requests at the edge: bots, SQL injection, known attack patterns
When to use it
Public sites, launches that attract bots
Trade-off / interview line
Can block real users if rules are too strict
Products
AWS WAF / Front Door WAF / Cloud Armor / Cloudflare
DDoS protection
What it is
Absorbs floods of junk traffic
When to use it
Usually included with the CDN or cloud
Trade-off / interview line
Mention it in one line; don't design it
Products
AWS Shield / Azure DDoS Protection / Cloudflare
Rate limiter
What it is
Caps requests per IP, user or API key in a time window (token bucket or sliding window)
When to use it
Spikes, bots, retry storms, protecting third-party quotas
Trade-off / interview line
Edge limits per IP; business limits per account ("2 orders per phone") in the API
Products
WAF rules, API gateway, Redis counters
Waiting room / virtual queue
What it is
Holds users on a "you're in line" page and lets them in at a fixed rate
When to use it
When demand far exceeds what you can serve (big launches)
Trade-off / interview line
Protects everything behind it, but it's a worse experience. Often keep it behind a flag.
Products
Cloudflare Waiting Room, Queue-it, Akamai
API gateway
What it is
One front door for APIs: auth, rate limits, routing, API keys
When to use it
Many APIs or external developers
Trade-off / interview line
Overkill for one small service; a load balancer is enough
Products
API Gateway / Azure API Management / Apigee
Load balancer
What it is
Spreads requests across several API instances and skips unhealthy ones
When to use it
As soon as you have 2+ instances (always, for availability)
Trade-off / interview line
L4 balances TCP connections (fast, simple). L7 understands HTTP (routes by path, ends TLS). Usually pick L7.
Products
ALB, NLB / Azure Load Balancer, App Gateway / Cloud Load Balancing
Reverse proxy
What it is
A server in front of your app that handles TLS, compression and routing
When to use it
Often built into the load balancer or platform
Trade-off / interview line
Nginx and Envoy are the classics
Products
Nginx, Envoy, Traefik

2. Compute: where your code runs

API service (stateless)
What it is
Your backend: handles requests, keeps no user state in memory, so any instance can serve any request
When to use it
Always
Trade-off / interview line
"Stateless, so I scale it by adding instances." State goes in the DB or cache.
Products
Any web framework
Monolith (modular)
What it is
One deployable service with clear internal modules
When to use it
Small teams, short timelines: the default
Trade-off / interview line
Simple to build, deploy and debug. Splitting later is fine.
Microservices
What it is
Many small services, each owning its own data
When to use it
Large teams that need to deploy independently
Trade-off / interview line
Network calls, distributed failures, more ops. Usually the wrong answer for a small business.
Managed containers
What it is
Run Docker images without managing servers or a cluster
When to use it
Default hosting for an API and workers
Trade-off / interview line
Good middle ground. Scale-out takes 1 to 5 minutes.
Products
ECS Fargate / Azure Container Apps / Cloud Run
Kubernetes
What it is
A cluster that schedules containers
When to use it
Many services, a platform team
Trade-off / interview line
Powerful, but heavy to run. Say why you're not using it.
Products
EKS / AKS / GKE
Serverless functions
What it is
Code that runs per event; you pay per call
When to use it
Spiky, short tasks; webhooks; glue code
Trade-off / interview line
Cold starts; concurrency limits (AWS: 1,000 per region by default); time limits
Products
Lambda / Azure Functions / Cloud Functions
Autoscaling
What it is
Adds or removes instances based on CPU, requests or queue depth
When to use it
Gradual traffic changes
Trade-off / interview line
Too slow for a 5-minute surge. That's why you pre-scale before a known event.
Products
Built into each platform
Background worker
What it is
A process that pulls jobs from a queue and does slow work
When to use it
Emails, SMS, image processing, report generation
Trade-off / interview line
Scale on queue depth. Make jobs idempotent, since they may run twice.
Products
Same platforms as the API
Scheduled job (cron)
What it is
Code that runs on a timer
When to use it
Nightly reports, cleanup, reconciliation
Trade-off / interview line
Make sure only one copy runs at a time (a lock or a single-instance job)
Products
EventBridge Scheduler / Container Apps jobs, Logic Apps / Cloud Scheduler
Sweeper job
What it is
A scheduled job that finds stale state and fixes it: expired holds, stuck orders, abandoned carts
When to use it
Any design with holds, reservations or timeouts
Trade-off / interview line
"Every minute, release holds past their expiry. Before releasing, check the provider in case payment succeeded."
Products
A cron job plus a DB query on an indexed expires_at
Reconciliation job
What it is
Compares your records with the outside source of truth (Stripe, bank) and fixes gaps
When to use it
Anything involving money or external state
Trade-off / interview line
Catches lost webhooks and partial failures. "Trust, but reconcile."
Products
Scheduled job

3. Databases

3a. Which kind of database

Relational (SQL)
What it is
Tables with rows, joins, ACID transactions, constraints
Good for
Orders, payments, inventory, users: anything where correctness matters. The default.
Weak at
Huge write scale on one primary (you shard by hand)
Products
Postgres, MySQL / RDS, Aurora / Azure Database for PostgreSQL / Cloud SQL
Key-value
What it is
Get and put by key, very fast, scales horizontally
Good for
Sessions, carts, counters, simple lookups at huge scale
Weak at
Queries other than by key; multi-item transactions are limited
Products
DynamoDB / Cosmos DB / Bigtable; Redis
Document
What it is
Stores JSON documents, flexible schema
Good for
Content, catalogs, data whose shape varies
Weak at
Joins, strict cross-document consistency
Products
MongoDB / Cosmos DB / Firestore
Wide-column
What it is
Huge tables partitioned by key, built for writes
Good for
Time series, event logs, massive write volume
Weak at
Ad-hoc queries, transactions
Products
Cassandra, ScyllaDB / Bigtable
Search engine
What it is
Inverted index for full-text and filtered search
Good for
Product search, log search
Weak at
Being the source of truth; it's eventually consistent
Products
Elasticsearch, OpenSearch / Azure AI Search
Time-series
What it is
Optimized for timestamped metrics
Good for
Monitoring, IoT
Weak at
General app data
Products
Prometheus, InfluxDB, TimescaleDB
Graph
What it is
Nodes and edges
Good for
Social graphs, recommendations
Weak at
Most business apps
Products
Neo4j / Neptune / Cosmos DB Gremlin
Object storage
What it is
Files (blobs) by key, nearly unlimited, cheap
Good for
Images, videos, exports, backups, recordings
Weak at
Querying, small frequent updates
Products
S3 / Azure Blob Storage / GCS
Data warehouse
What it is
Columnar store for analytics over large data
Good for
Reports, dashboards, BI
Weak at
Serving live user requests
Products
Redshift / Synapse, Fabric / BigQuery; Snowflake

Interview line for picking Postgres: "My core write touches two rows that must change together, and Postgres does that in one transaction. At N writes a second it fits on one instance. I'd consider DynamoDB if writes grew past what one primary handles or I needed single-digit-ms reads at huge scale."

Interview line for DynamoDB: "Great at massive scale with predictable key lookups, and it has conditional writes. But each partition is limited (about 1,000 writes/s), so one hot item is a bottleneck, and multi-item transactions cost more and have limits."

3b. Database concepts to know

ACID transaction
What it is
Several changes that all happen or none do (Atomic, Consistent, Isolated, Durable)
Why it matters
"Reserve inventory and create the order in one transaction."
Isolation levels
What it is
How much concurrent transactions see each other (read committed, repeatable read, serializable)
Why it matters
Default read committed is fine if you use conditional updates or row locks
Index
What it is
A sorted lookup structure on a column
Why it matters
Every query in the hot path needs one. The sweeper needs one on expires_at.
Unique constraint
What it is
The DB rejects duplicate values
Why it matters
Idempotency keys, "one booking per seat per time slot"
Primary / replica
What it is
Writes go to the primary; replicas copy it for reads
Why it matters
Scale reads, survive failure. Replicas lag slightly, so never read inventory you're about to sell from a replica.
Failover
What it is
A replica is promoted when the primary dies
Why it matters
Managed DBs do it in about 30 to 60 s. Clients must retry.
Sharding / partitioning
What it is
Split data across several DBs by a key
Why it matters
Only when one primary can't keep up. Hard to undo; avoid in V1.
Connection pooling
What it is
A pooler holds a small set of DB connections shared by many app instances
Why it matters
Postgres allows only a few hundred connections. Without a pooler, scaling out the API exhausts the DB.
Backups / point-in-time restore
What it is
Restore the DB to any moment in the last N days
Why it matters
Defines your RPO
RPO / RTO
What it is
RPO: how much data you can lose. RTO: how long you can be down.
Why it matters
"RPO 5 minutes, RTO 1 hour" makes multi-region a choice you can argue, not a default.
CAP / consistency
What it is
In a network split, a distributed system chooses between consistency and availability
Why it matters
Money and inventory need strong consistency; likes and view counts can be eventual
Eventual consistency
What it is
Readers may see old data for a short while
Why it matters
Fine for caches, search and counters; never for "is this seat taken"

4. Caching

Cache
What it is
A fast copy of data, usually in memory
Note
Cuts DB reads and latency. Never the source of truth for money or inventory.
In-memory store
What it is
Redis (data structures, persistence, atomic ops) or Memcached (simple, pure cache)
Note
Redis is the usual pick. Products: ElastiCache / Azure Cache for Redis / Memorystore.
Cache-aside
What it is
The app checks the cache, on a miss reads the DB and fills the cache
Note
The most common pattern
Write-through
What it is
Every write updates the DB and the cache together
Note
Fresher cache, slower writes
TTL
What it is
How long a cached value lives
Note
Short TTL (1 to 5 s) during a spike is a big win with little staleness
Invalidation
What it is
Removing a cached value when the data changes
Note
Hard. A short TTL is often simpler.
Cache stampede
What it is
A popular key expires and thousands of requests hit the DB at once
Note
Fixes: one request refreshes while others wait (request coalescing), or serve stale while refreshing
Hot key
What it is
One key gets most of the traffic
Note
Replicate it, or cache it locally in each API instance for a second
Local (in-process) cache
What it is
Cache in the API's own memory
Note
Fastest, but each instance has its own copy

5. Async: queues, streams and events

Message queue
What it is
A list of jobs; workers take one, do it, and delete it
When to use it
Non-urgent work (emails, SMS), smoothing bursts, job processing
Products
SQS / Azure Service Bus, Storage Queues / Cloud Tasks, Pub/Sub; RabbitMQ
Log / stream
What it is
An append-only log many consumers can read and replay
When to use it
Event sourcing, analytics pipelines, very high throughput, replays
Products
Kafka / Kinesis / Event Hubs / Pub/Sub
Pub/sub
What it is
One message, many subscribers
When to use it
Fan-out: "order paid" goes to the kitchen, email and analytics
Products
SNS / Event Grid, Service Bus topics / Pub/Sub
Dead-letter queue (DLQ)
What it is
Where messages go after N failed attempts
When to use it
Always pair it with a queue, and alert on DLQ depth
Products
Built into most queues
At-least-once delivery
What it is
The queue may deliver a message twice
When to use it
So consumers must be idempotent
Exactly-once
What it is
Mostly a myth end to end
When to use it
Say: "at-least-once delivery plus idempotent consumers"
Backpressure
What it is
Slowing producers when consumers can't keep up
When to use it
Queue depth as a signal; cap worker concurrency so downstream systems survive
Outbox pattern
What it is
Write the event to an outbox table in the same DB transaction, and a relay publishes it
When to use it
Avoids "DB committed but the message was never sent"

Queue vs stream, in one line: "A queue is a to-do list where each job is done once. A stream is a log that many readers can replay. For sending texts I need a queue, not Kafka."

6. Correctness patterns (the invariants)

Atomic conditional update
What it is
Change a row only if a condition holds, in one statement
Example
UPDATE slots SET reserved = reserved + 2 WHERE id = 7 AND reserved + 2 <= capacity. 0 rows updated means sold out.
Pessimistic lock
What it is
Lock the row while you work: SELECT ... FOR UPDATE
Example
When the logic is too complex for one statement. Keep the transaction short.
Optimistic lock
What it is
Read a version number, update only if it hasn't changed, retry otherwise
Example
Low contention, such as editing a profile
Holds / reservations with expiry
What it is
Reserve the inventory first, pay within N minutes, a sweeper frees expired holds
Example
Seats, limited stock, time slots
Idempotency key
What it is
A unique id per user action. Repeating the request returns the first result instead of doing it again.
Example
Client sends Idempotency-Key; unique constraint in the DB; same key passed to Stripe
Webhook dedupe
What it is
Store each provider event id; ignore repeats
Example
Stripe can send the same event more than once
State machine
What it is
A status that only moves forward: held, then paid or expired
Example
A late or duplicate event can't move an order backward
Saga
What it is
A multi-step process where each step has an undo step
Example
Booking a flight and a hotel; refund if the second step fails
Distributed lock
What it is
A lock shared across machines (Redis, ZooKeeper)
Example
Usually avoid. A DB constraint or conditional update is simpler and safer.
Reconciliation
What it is
Periodically compare with the source of truth and fix gaps
Example
Nightly or every few minutes against Stripe

7. Third-party services

Payment provider
What it does
Charges cards, handles fraud checks, 3-D Secure and payouts
What to know
Hosted checkout keeps card data off your servers (much smaller PCI scope). Flow: create a session or PaymentIntent, user pays on the provider's page, the provider sends a webhook. Use idempotency keys on every call. Test mode for load tests. Rate limit about 100 requests/s by default in live mode; ask to raise it before a launch.
Products
Stripe, Adyen, Square, PayPal
Webhook
What it does
The provider calls your URL when something happens
What to know
Verify the signature, return 200 fast, process async, dedupe on event id, and expect it late or twice
SMS / voice
What it does
Sends texts and calls
What to know
Per-number and per-account rate limits; carrier filtering; async plus retries
Products
Twilio, Azure Communication Services, Vonage
Email
What it does
Sends transactional email
What to know
Async, with retries; watch bounces
Products
SendGrid, SES, Postmark
Auth / identity
What it does
Login, OAuth, social sign-in, tokens
What to know
Don't build your own. Guest checkout often skips login entirely.
Products
Auth0, Cognito, Entra ID, Firebase Auth
Feature flags
What it does
Turn features on or off at runtime without a deploy
What to know
Kill switches, staged rollouts, waiting room toggle
Products
LaunchDarkly, Azure App Configuration, Unleash, or a DB table
Maps / geo
What it does
Addresses, distance, delivery zones
What to know
Cache results; per-call cost
Products
Google Maps, Mapbox, Azure Maps

8. Reliability patterns

Timeout
What it is
Give up on a call after N ms
Interview line
"Every outbound call has a timeout. The default is often infinite."
Retry with exponential backoff and jitter
What it is
Retry after 100 ms, 200, 400..., with randomness
Interview line
Jitter stops all clients retrying at the same instant. Retry only idempotent calls.
Circuit breaker
What it is
After repeated failures, stop calling a dependency for a while and fail fast
Interview line
Protects your threads and the struggling dependency
Bulkhead
What it is
Separate resource pools per dependency
Interview line
A slow Stripe can't eat all the threads checkout needs
Graceful degradation
What it is
Turn off non-essential features under load
Interview line
Hide photos, recommendations, the live status page
Load shedding
What it is
Reject some requests early (HTTP 429/503) to keep the rest fast
Interview line
Better than everyone timing out
Kill switch
What it is
A flag that turns off a feature instantly
Interview line
"Pause new orders" when payments are down
Health checks
What it is
The load balancer pings /health and removes bad instances
Interview line
Liveness (is it running) vs readiness (can it take traffic)
Multi-AZ
What it is
Instances in several data centers in one region
Interview line
Cheap and usually managed: do it
Multi-region
What it is
A full copy in another region
Interview line
Expensive and complex. Justify with RTO/RPO, or say no.
Pre-scaling / pre-warming
What it is
Scale up before a known event
Interview line
Autoscaling reacts in minutes; a promo spike arrives in seconds

9. Observability

Metrics
What it is
Numbers over time: request rate, errors, latency, queue depth
Products
Prometheus, CloudWatch, Azure Monitor, Datadog
Logs
What it is
Event records; structured JSON is searchable
Products
CloudWatch Logs, Log Analytics, ELK
Traces
What it is
One request followed across services, with timings
Products
OpenTelemetry, X-Ray, Application Insights
Dashboards
What it is
The metrics you watch on launch day
Products
Grafana, Azure dashboards, Datadog
Alerts
What it is
Page someone when a metric crosses a threshold
Products
PagerDuty, Opsgenie, Azure Monitor alerts
Percentiles
What it is
p50 = typical, p95 / p99 = the slow tail
Products
"p95 under 500 ms" beats "average 200 ms"
Golden signals
What it is
Latency, traffic, errors, saturation
Products
The default dashboard
Business metrics
What it is
Orders/min, held vs paid, inventory left
Products
Often the first sign something is wrong
SLI / SLO / error budget
What it is
SLI: a measured indicator. SLO: the target (99.9%). Error budget: how much failure is allowed.
Products
"Our SLO is 99.9% of checkouts under 1 s during the event."
Runbook
What it is
A written "if this alert fires, do this"
Products
Every alert gets an owner and a runbook entry

10. Release and launch operations

CI/CD
What it is
Automatic build, test and deploy on merge
Note
GitHub Actions, Azure DevOps
Rolling deploy
What it is
Replace instances a few at a time
Note
The default on most platforms. Kills in-flight work unless shutdown is graceful.
Blue-green
What it is
Run the new version next to the old and switch traffic at once
Note
Instant rollback by switching back
Canary
What it is
Send 1 to 5% of traffic to the new version first and watch metrics
Note
Catches bad releases early
Rollback
What it is
Return to the last good version
Note
Only real if you've practiced it
Code freeze
What it is
No deploys for a window around the event
Note
"Nothing ships during the game."
Load test
What it is
Simulate expected traffic at 2 to 3x the peak
Note
k6, Locust, JMeter, Azure Load Testing. Needs a pass bar.
Game day
What it is
A rehearsal: run the load test, flip every switch, fake an outage
Note
Finds the gaps in the runbook
Chaos testing
What it is
Kill things on purpose to see what breaks
Note
A game day is the small-business version
Capacity planning
What it is
The math from peak load to instance counts and DB size
Note
Your back-of-envelope numbers, written down

11. Security basics (one line each in an interview)

TLS
HTTPS everywhere, ended at the load balancer or CDN
Authn vs authz
Authentication = who you are; authorization = what you're allowed to do
Secrets
Keys in a secrets manager (Key Vault, Secrets Manager), never in code
PCI
Hosted checkout keeps card data off your servers, which shrinks PCI scope a lot
PII
Store as little as possible; encrypt at rest (managed DBs do it by default)
Least privilege
Each service gets only the permissions it needs (managed identities)
